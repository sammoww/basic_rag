Python Pipeline & Execution Nodes

Every file, function, class, input, and output mapped step-by-step

⚡ 1. Live Chat Orchestration (app.py)

// The exact LangChain LCEL chain executing in your Python process:
rag_chain = ( {"context": retriever | format_docs, "question": RunnablePassthrough()} | prompt | llm | StrOutputParser() )
NODE 01
Parallel Context Retrieval & Question Pass-through
app.py 100% Local Python

Splits the incoming question into two parallel operations: Branch A uses vector_store.as_retriever() to search FAISS and formats chunks with format_docs(). Branch B passes the raw question through unchanged using RunnablePassthrough().

{"context": retriever | format_docs, "question": RunnablePassthrough()}
Input Data
str: "What is RAG and how does it reduce hallucinations?"
Output Data
dict: {"context": "Retrieval-Augmented Generation...", "question": "What is RAG..."}
│   Pipe Operator (|) passes dictionary forward
NODE 02
Prompt Template Formatter
app.py 100% Local Python

Class: ChatPromptTemplate.from_template()
Fills the dictionary values into the system template string (controlled by your Strict Mode toggle).

template = """Answer the question based ONLY on the following context:\n{context}\n\nQuestion: {question}"""
Input Data
dict: {"context": "...", "question": "..."}
Output Data
PromptValue (Formatted System + User instructions)
│   Pipe Operator (|) passes formatted prompt forward
NODE 03
Generative AI Inference (with Fallback)
app.py HTTP API Request

Classes: ChatGoogleGenerativeAI (Primary: gemini-3.5-flash) with ChatGroq fallback.
Sends HTTP POST with the full prompt to Google. If rate-limited or unavailable, routes seamlessly to Groq.

gemini_llm = ChatGoogleGenerativeAI(model="gemini-3.5-flash")
llm = gemini_llm.with_fallbacks([groq_llm])
Input Data
PromptValue string via HTTP payload
Output Data
AIMessage (text content + token usage metadata)
│   Pipe Operator (|) passes AIMessage forward
NODE 04
String Output Parser
app.py 100% Local Python

Class: StrOutputParser()
Extracts the pure text string from the AIMessage object so Streamlit can render it cleanly.

response = rag_chain.invoke(prompt) // Returns clean string
Input Data
AIMessage(content="Retrieval-Augmented Generation...", id="...")
Output Data
str: "Retrieval-Augmented Generation (RAG) is a technique..."

📚 2. Text Splitting & Database Ingestion (vector_store.py)

STEP A
File Reading
vector_store.py Local File I/O

Class: TextLoader(file_path, encoding='utf-8')
Reads raw data/sample.txt into Python memory as a single Document object.

↓ Sends single raw document
STEP B
Recursive Character Text Splitter
vector_store.py Local String Logic

Class: RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)
Splits on paragraphs (\n\n), sentences (\n), then spaces. Leaves 50 overlapping characters between chunks so sentences aren't chopped mid-thought.

Input
1 Document of 1,200 characters
Output
List of 2-3 chunked Documents (~500 chars each)
↓ Sends chunk text over HTTP
STEP C
Google Embeddings API
vector_store.py Cloud Embeddings

Class: GoogleGenerativeAIEmbeddings(model="models/gemini-embedding-2")
Takes each chunk of English text and translates its semantic meaning into a list of 768 floating-point numbers.

↓ Returns vector numbers to disk
STEP D
FAISS Index Creation
vector_store.py Local FAISS Index

Functions: FAISS.from_documents(chunks, embeddings) & vector_store.save_local(DB_DIR)
Builds an index of vectors and serializes them into the faiss_db/ folder on your hard drive.
